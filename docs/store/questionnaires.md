## 3. Google Play 대상 연령 및 콘텐츠 (Target audience and content) [S5][S6][S7][S8]

**추천 대상 연령: 9~12세, 13~15세, 16~17세, 18세 이상** (혼합 대상, 아동 포함)

- 이유: 회사원 코미디라 어른이 주 대상이지만 그림·조작이 아동에게도 매력적이고 우리 원칙이 "전 연령 가족(P4)"이에요. 아동 연령을 빼면 Play가 "아동에게 어필할 수 있음" 검토에서 지적할 수 있고, 가족 원칙과도 맞지 않아요.
  8세 이하(5세 이하·6~8세)를 넣지 않는 이유: 한국어 대사·미션 설명을 읽어야 하는 게임이라 주 대상이 아니에요. 넣어도 의무는 같으니(아래) 대표님이 넣어도 돼요.
- **아동 포함을 고르면 생기는 의무 (Families 정책):**
  1. 아동에게 보일 수 있는 광고는 **Families 자체 인증 광고 SDK**로만 → Google AdMob은 인증 목록에 있음 [S6]. 미디에이션을 켜면 인증된 광고 소스만 써야 함 (지금은 미디에이션 없음).
  2. 아동에게는 **비맞춤형** 광고만, 관심 기반·리마케팅 금지 → 우리는 모든 요청에 아동 대상 처리 태그(TFCD)를 붙여 **모든 사용자를 아동처럼** 처리. 그래서 "중립적 나이 확인 화면"이 필요 없어요(어른에게만 다른 광고를 보낼 일이 없음).
  3. **광고 ID(AD_ID) 전송 금지** → 아동 대상 태그 요청은 GMA SDK가 광고 ID를 보내지 않음 [S7]. 그래도 매니페스트에 `com.google.android.gms.permission.AD_ID` 권한이 **병합되어 들어오지 않게 제거**(`tools:node="remove"`)해야 하고, Play Console "광고 ID" 신고는 "사용 안 함"으로 답함. ← **개발 확인 항목** (release-checklist.md 2.3)
  4. 광고 형식: 속이거나 실수로 누르게 하는 광고 금지, 보상형은 사용자가 고른 경우만 → 우리 설계(선택 버튼, 닫힘으로 지급 안 함)와 맞음.
  5. 인앱 구매: 아동을 압박하는 문구 금지 → 결과·실패 화면에 구매 유도 없음, 카운트다운 없음(설계 2장).
  6. 개인정보처리방침 필수, 아동 관련 법(COPPA, 한국 개인정보 보호법 만 14세 미만 규정 등) 준수 책임은 개발자.
- **스토어 등록정보가 아동에게 어필하나요?** → "예" (혼합 대상과 일치).
- **AdMob 앱 설정:** AdMob 콘솔에서도 앱을 "아동 대상(child-directed)" 으로 표시 (release-checklist.md 1.3).

## 4. Google Play 데이터 보안 (Data safety) [S11]

원칙: 개발자 자신은 아무것도 수집하지 않지만, **앱에 들어간 SDK(AdMob)가 기기 밖으로 보내는 데이터는 우리 앱의 "수집"으로 신고**해야 해요. 기기 안에서만 처리하는 데이터(진행 저장, 구매 확인 결과)는 "수집"이 아니에요.
아래 데이터 유형은 Google 공식 "AdMob Play 데이터 공개" 페이지의 표를 기준으로 했고, **입력 직전에 그 표(현재 SDK 버전)와 다시 맞춰 주세요** [S11].

| 질문 | 답 |
|---|---|
| 앱이 필수 사용자 데이터 유형을 수집하거나 공유하나요? | **예** (AdMob SDK) |
| 전송 중 데이터가 모두 암호화되나요? | **예** (AdMob은 TLS 사용 [S11]) |
| 사용자가 데이터 삭제를 요청할 수 있나요? | **아니요 / 해당 없음**에 가까움 — 개발자가 보관하는 사용자 데이터가 없음. 콘솔이 방법을 요구하면 "앱 데이터 삭제 = 앱 삭제, 광고 데이터는 Google 정책" 안내 URL로 privacy.html |
| 계정 생성 | 앱에 계정 없음 → 계정 삭제 URL 불필요 |
| Families 정책 준수 확인 체크 | 예 |

| 데이터 유형 | 수집 | 공유 | 처리 방식 | 목적 | 비고 |
|---|---|---|---|---|---|
| 위치 › 대략적인 위치 | 예 | 아니요* | 자동(사용자 선택 불가) | 광고, 사기 방지·보안, 분석 | IP 주소에서 추정 |
| 앱 활동 › 앱 상호작용 | 예 | 아니요* | 자동 | 광고, 분석, 사기 방지 | 광고 노출·클릭 |
| 앱 정보 및 성능 › 비정상 종료 로그, 진단 | 예 | 아니요* | 자동 | 분석, 사기 방지 | 광고 SDK 진단 |
| 기기 또는 기타 ID | 예 | 아니요* | 자동 | 광고, 분석, 사기 방지 | 아동 대상 태그로 **광고 ID는 보내지 않지만** 앱 세트 ID 등 다른 기기 ID는 남을 수 있어 신고 |
| 개인 정보(이름·이메일 등), 금융 정보, 연락처, 사진, 오디오, 파일, 메시지, 건강 | 아니요 | 아니요 | | | 앱에 로그인 없음 |
| 금융 정보 › 구매 기록 | **아니요** | 아니요 | | | 결제는 Google Play가 처리하고, 앱은 구매 여부를 기기 안에서만 확인 |

\* "공유": Google Play 정의상 **서비스 제공업체가 개발자를 대신해 처리**하는 전송은 공유가 아니에요. AdMob 공식 표가 "공유"로 표시하는 항목이 있으면 그 표를 따르세요.

## 5. Apple 앱 개인정보 보호 라벨 (App Privacy) [S12][S13]

- **"이 앱에서 데이터를 수집합니까?" → 예** (AdMob SDK가 수집. Apple도 제3자 SDK 수집을 앱이 신고하게 함)
- **추적(Tracking) → 아니요**: ATT를 요청하지 않고 IDFA를 쓰지 않으며, 아동 대상·비맞춤형 요청이라 다른 회사 데이터와 연결해 광고에 쓰지 않음. → `NSUserTrackingUsageDescription` 없음, 라벨 "사용자를 추적하는 데 사용되는 데이터" 칸 비움.
- 아래는 Google "App Store data disclosure"(AdMob iOS) 표 기준 초안. **입력 직전 그 표와 다시 대조** [S12].

| 데이터 유형 | 용도 | 사용자에게 연결 | 추적 |
|---|---|---|---|
| 위치 › 대략적인 위치 | 제3자 광고, 분석 | 아니요 | 아니요 |
| 식별자 › 기기 ID (ATT 없이는 IDFA가 0으로만 전달, 그 밖의 기기 식별 정보) | 제3자 광고, 분석 | 아니요 | 아니요 |
| 사용 데이터 › 제품 상호작용 | 제3자 광고, 분석 | 아니요 | 아니요 |
| 사용 데이터 › 광고 데이터 | 제3자 광고, 분석 | 아니요 | 아니요 |
| 진단 › 충돌 데이터, 성능 데이터, 기타 진단 데이터 | 분석, 앱 기능 | 아니요 | 아니요 |
| 구입 항목 › 구입 내역 | **수집 안 함** (StoreKit 결제는 Apple이 처리, 앱은 기기에서 권한만 확인) | | |
| 연락처 정보, 건강, 금융, 사용자 콘텐츠, 검색 기록 등 | 수집 안 함 | | |

- **개인정보 매니페스트:** Google Mobile Ads SDK 11.2.0 이상은 자체 `PrivacyInfo.xcprivacy`를 포함 [S12]. 앱 자체 매니페스트(UserDefaults 등 "필수 사유 API")는 Capacitor·플러그인 포함 여부를 빌드에서 확인 (release-checklist.md 2.2).

## 8. 수출 규정 준수 (암호화) [S15]

- 앱 코드는 자체 암호화를 쓰지 않고, 통신은 OS가 제공하는 HTTPS(광고 SDK·StoreKit·원격 설정)뿐 → **면제 대상 암호화만 사용**.
- App Store Connect 질문에는 "표준 암호화만 사용 / 면제 대상"으로 답함 → 문서 업로드 불필요.
- 매번 묻지 않게 iOS `Info.plist`에 `ITSAppUsesNonExemptEncryption` = `NO` 추가 권장 (현재 Info.plist에 없음 → 개발 작업, release-checklist.md 2.2).
- 주의: 광고 SDK 같은 제3자 라이브러리가 비면제 암호화를 쓰면 답이 달라져요. Google Mobile Ads SDK는 시스템 TLS를 쓰는 것으로 알려져 있지만, 공식 확인 문서는 이번 검색에서 찾지 못했어요(불확실).
- Google Play: 별도 수출 규정 질문 없음.

## 9. Apple 키즈 카테고리 — **넣지 않기를 추천** [S16][S17]

이유:
1. **가이드라인 1.3**: 키즈 카테고리 앱은 "제3자 분석이나 제3자 광고를 포함하지 않아야(should not)" 하고, 제한적 예외(같은 1.3 조건을 지키는 서비스, 사람이 검토한 문맥 광고 등)만 허용돼요. AdMob 보상형 광고가 이 예외를 통과한다는 보장이 없고, 개발자 포럼에는 분석·광고 SDK 때문에 1.3으로 반려된 사례가 여럿 있어요.
2. 같은 1.3은 키즈 카테고리 앱이 **기기 정보도 제3자에게 보내지 말 것**을 요구 → AdMob은 IP·기기 ID를 Google로 보내므로 충돌.
3. 키즈 카테고리는 외부 링크·권한 요청·**구매 화면 앞에 보호자 확인(parental gate)**이 필요하고, 연령대(5세 이하 / 6~8세 / 9~11세)를 하나 골라야 해요. 우리 게임은 어른(회사원)이 주 대상인 전 연령 게임이라 맞지 않아요.

넣지 않아도 남는 의무 — **가이드라인 5.1.4**: 아동을 대상으로 하거나 아동이 쓸 수 있는 앱은 COPPA·GDPR 등 아동 개인정보 법을 지켜야 하고, 아동에게서 개인정보를 모으지 말아야 해요. → 우리는 개발자 수집 0, 광고는 아동 대상 처리·비맞춤형·ATT 없음으로 이미 맞춰 둠. 연령 등급은 4+로 두되 "키즈" 카테고리는 선택하지 않음.

## 10. 남는 불확실성

- AdMob Play/App Store 공개 표의 **정확한 데이터 유형·"공유" 여부**는 이번에 공식 표 전체를 열어 보지 못했어요(WebFetch 금지, 검색 요약만). 입력 직전 [S11][S12] 표와 대조 필요.
- Apple 연령 설문의 **정확한 문항 문구**(특히 2026 추가 소셜 미디어 문항)는 콘솔 화면 기준으로 확인.
- 폭력·알코올 두 칸은 대표님 판단(그림 확인) 필요. 보수적으로 답하면 iOS 9+~13+가 될 수 있음.
- 만 14세 미만 사용자와 광고 SDK의 기기 정보 처리(한국 개인정보 보호법 법정대리인 동의)는 **법무 검토 권장** — 우리는 아동 대상 태그·비맞춤형으로 최소화했지만, 법적 판단은 이 문서 범위 밖이에요.
