# 실력별 봇 프로필 (밸런스 측정용)

작성 2026-11-03 · 코드 `src/game/bot-profiles.ts` · 하네스 `tests/office/balance.harness.ts`

> **이 수치는 추정치입니다.** 사람 플레이 기록에 맞춘 값이 아니라, 리듬·러너 게임에서 흔히 보이는 오차 크기를
> 근거로 정한 가정입니다. 통과율 표는 "이 가정의 봇이 깨는 비율"이지 실제 플레이어 통과율이 아닙니다.
> 사람 데이터가 생기면 이 표의 숫자부터 다시 맞춥니다.

## 구조

기준 봇(`src/game/bot.ts`, 거의 완벽)을 감싸서 사람처럼 틀리게 만듭니다. 기준 봇 코드는 고치지 않았습니다.
봇이 매 프레임 보는 세션을 살짝 바꾼 "보이는 세상"을 넘기는 방식입니다.

| 요소 | 모델 | 구현 |
|---|---|---|
| 입력 타이밍 오차 | 목표 비트마다 N(bias, sd) 한 번 (+ = 이르게), 공중 부스트마다 추가로 N(0, boostSd) | 봇에게 넘기는 시각을 그만큼 밀어 줌 |
| 돌발 공격 반응 지연 | drop·chaser·뒤 빔(“!”가 WARN_LEAD=1.0 s 전에만 뜨는 것)은 `WARN_LEAD − 반응시간` 전까지 안 보임. 반응시간 = max(min, N(mean, sd)) | 해당 비트를 그때까지 숨김 |
| 입력 놓침 | 장애물 비트마다 `missP × 동작 가중치 × 압박` 확률로 아예 안 봄 | 비트 숨김 |
| 잘못된 동작 | `wrongP × 동작 가중치 × 압박` 확률: 숙이기↔점프, 부스트 1회 부족, 드론에 2단 점프, 레인 단독 비트는 놓침 처리 | 비트 내용을 바꿔서 보여 줌 |
| 레인 스와이프 실수 | 레인 비트마다 `laneErrP` 확률로 첫 스와이프가 반대쪽 (비트당 1회), 스와이프 간격 ≥ laneSettle | 레인 출력 가로채기 |
| 수집 미션 | 수집 파트의 동전만 `greed` 확률로 노림 (1단 점프 + 동전 레인 이동, 위 오차 모두 적용) | 동전 비트를 "그 레인으로 가서 1단 점프" 비트로 보여 줌 |

- **동작 가중치(MOVE_WEIGHT):** jump·beam·slide·lane 1, drone 1.2, double·high 1.3, drop·gate·pulse 1.5,
  chaser 1.6, triple·rear 1.8, lanejump 2. 복합·돌발 동작일수록 실수가 잦다는 가정입니다.
- **압박(pressure):** 앞 장애물과 간격이 0.9 s(PRESSURE_GAP)보다 짧으면 실수 확률이 선형으로 최대 2배.
  밀도·간격 손잡이가 통과율에 반영되게 하려는 장치입니다(없으면 간격을 좁혀도 봇 결과가 거의 안 변합니다).
- **결정성:** 모든 무작위 값은 (런 시드, 비트 id, 용도) 해시로 뽑습니다. 같은 시드면 같은 런이 나옵니다.
  레이아웃 시드와 봇 시드는 다른 흐름(`seed ^ 0x9e3779b9`)입니다.

## 프로필 값

| 값 | 캐주얼 | 보통 | 숙련 | 근거(추정) |
|---|---|---|---|---|
| timingSd | 70 ms | 45 ms | 20 ms | 리듬게임 탭 오차 분포: 초보 60–80 ms, 숙련 15–25 ms 정도 |
| timingBias | +10 ms | +5 ms | 0 | 보이는 박자에는 살짝 이르게 누르는 경향 |
| boostSd | 35 ms | 22 ms | 10 ms | 연타 간격은 첫 탭보다 안정적 |
| reaction mean / sd / min | 450 / 120 / 250 ms | 350 / 80 / 200 ms | 250 / 50 / 150 ms | 모바일 시각 자극 선택 반응 시간대 |
| missP | 2.0 % | 0.8 % | 0.15 % | 캐주얼이 1단계(약 24장애물, 체력 3)를 거의 항상 깨도록 맞춤 |
| wrongP | 1.5 % | 0.6 % | 0.1 % | 같은 기준 |
| laneErrP | 8 % | 4 % | 1 % | 왼손 스와이프 방향 착각 |
| laneSettle | 160 ms | 130 ms | 100 ms | 기준 봇은 100 ms; 생성기는 사람 속도 300 ms/레인(LANE_STEP)을 가정 |
| greed | 85 % | 92 % | 97 % | 수집 미션에서 동전을 노리는 비율 |

보정 결과(현재 5단계, 시드 200): 숙련 1단계 100%, 캐주얼 1단계 93.6%(칼퇴준 95.5%). → `baseline.md`

## 민감도 (캐주얼, 시드 40 × 4캐릭터, 5d60bf7)

어떤 오차가 실제로 실패를 만드는지 하나씩만 켜서 본 결과입니다 (통과율 / 평균 피격).

| 켠 것 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| 전부 | 98% / 0.46 | 94% / 0.62 | 88% / 0.78 | 90% / 0.81 | 87% / 0.99 |
| 타이밍 오차만 | 100% / 0.06 | 100% / 0.04 | 100% / 0.04 | 100% / 0.04 | 100% / 0.08 |
| 반응 지연만 | 100% / 0 | 100% / 0 | 100% / 0 | 100% / 0 | 100% / 0 |
| 스와이프 실수만 | 100% / 0 | 100% / 0 | 100% / 0 | 100% / 0 | 100% / 0 |
| 놓침·잘못만 | 99% / 0.40 | 94% / 0.59 | 88% / 0.77 | 91% / 0.78 | 89% / 0.88 |
| 타이밍 오차 2배(140 ms)만 | 69% / 1.54 | 59% / 1.86 | 44% / 2.24 | 49% / 2.20 | 43% / 2.27 |

(압박 계수 추가 전 측정)

읽는 법:
- 판정은 타이밍에 관대합니다. 70 ms 오차는 거의 피격을 만들지 않고, 140 ms부터 급격히 무너집니다.
- WARN_LEAD 1.0 s는 450 ms 반응에도 여유가 있고, 스와이프 실수는 대부분 고쳐집니다.
- 따라서 지금 통과율은 거의 **놓침·잘못 확률 × 장애물 수 × 동작 가중치**로 결정됩니다. 장애물 수와
  동작 구성이 가장 강한 손잡이이고, 간격(밀도)은 압박 계수를 통해서만 들어갑니다.

## 한계

- 사람 데이터가 없으므로 절대값보다 **단계 간 상대 비교와 패치 전/후 비교**에 씁니다.
- 실수는 비트마다 독립이라고 가정합니다(사람은 한 번 맞으면 연달아 흔들리기도 합니다).
- 학습 효과(재도전할수록 잘함)는 없습니다. 통과율은 "처음 보는 레이아웃 한 번"의 확률입니다.
- 봇은 수집 미션이 아닌 파트의 동전·방패·하트를 일부러 노리지 않습니다(기준 봇과 같음).
